01 · 入门

怎么用这份目录

三个入口，按顺序看：

  • 常用精选：放的是基本天天都在用的工具。
  • 小众优选：没什么名气，东西是真有用。
  • 实时热榜：GitHub 数据自己抓，分天 / 周 / 月三个窗口，只看新上榜的仓库（天 200 星、周 500 星、月 1500 星起步），星标实时排序。

编号标本卡随便点一张，弹窗里就是完整介绍和功能特点。

顶部工具栏有五样东西：

  • 搜索：名字、用途、标签都能模糊查，输「终端」或「图像生成」就行。
  • 分类：开发、AI、设计、系统、效率、网络、媒体、主机八个大类，按色脊筛。
  • 标签：平台、特性、授权三组交叉筛。一组里可以多选，组与组之间取交集。
  • 语言：按仓库的主语言筛。
  • 排序：默认走精选顺序，想按名称 A–Z 也可以。

热榜页会多出「星标门槛」和「刷新」两个控件。

编号这么分：常用精选占 001–221，小众优选 222–500，热榜实时条目一律标 LIVE。星标数是抓取那一刻的 GitHub 读数，本站不维护它；你看到时它早成了「昨天的新闻」，别较真。

每张标本卡只说清几件事：

  • 编号：它的身份标识。发现错误或者想建议收录，直接报编号——「022 GIMP 的许可证写错了」——比贴截图清楚得多。
  • 左侧色脊：它属于哪一类。
  • 卡底的星标 / 语言 / 许可证：都来自项目的 GitHub 仓库，当参考就行。
  • 查看介绍：点一下，完整介绍、功能特点、仓库链接全出来了。

搜索和筛选，各有各的用法：

  • 搜索：适合「大概知道要什么」。叫不出工具名，只清楚它干什么，先把用途丢进搜索框。
  • 筛选：适合「明确知道要什么」。心里有个谱，想在同类里比比看，先按分类筛，再挨个点开。

两条路都找不到，多半是你的措辞跟站内标签对不上。换个词再试一遍。

02 · 开发

挑代码编辑器

编辑器是你天天盯着的东西，选错了，一周就够把耐心磨没。路大概三条，各要你在学费上押不同的注：

  • 装好就能用：VS Code。插件生态数它最全，Git、调试、终端都自带，不知道该选什么时就选它。
  • 键盘流：Neovim。用 Lua 配置，LSP 是一等公民，启动毫秒级；学习曲线陡是它的价。跟 fzf、mise 这类工具搭着用是常规操作。
  • 速度和协作：Zed。Rust 加 GPU 渲染，招牌是多人实时协作，自称「下一代编辑器」，生态还在成长期。

或者你只想「打开就改文件」，配置一概不碰：micro 差不多是终端里的记事本，Ctrl+S 保存，鼠标能点，没有模态编辑那道坎。

对着自己的场景对号入座，更快：

  • 刚学编程，想一打开就有产出 → VS Code。扩展市场几万个，缺什么装什么；只是别头一天就装二十个，多一个扩展，就多一分启动延迟和注意力干扰。
  • 整天泡在终端里，手不想离开键盘 → Neovim。模态编辑的适应期按周算，练成肌肉记忆后就很难回头；内置 :help 加官方快速入门，从头读一遍比刷碎片教程省事。
  • 需要多人实时编辑，或者更在乎快 → Zed。多人实时协作这一项，另外两家眼下追不上；但它的生态比 VS Code 年轻，个别语言的支持还差一截。
  • 偶尔改一个配置文件，不想装任何大件 → micro，装完就可以忘掉它。

三家各一句话：VS Code 是「工具链平台」，Neovim 是「效率系统」，Zed 是「性能赌注」。先想清楚你要哪个，再装。

03 · AI

开源 AI 工具：把它们在本地跑起来的路子

要用 AI，又不想把一切交给闭源 API，本地这套栈按层搭：

  • 推理层：本地大模型先试 Ollama，一条命令把模型拉下来跑。想把硬件榨到最后一滴，再去看 llama.cpp（量化推理）和 vLLM（高吞吐服务）。
  • 应用层：应用框架交给 LangChain；给模型套界面用 Gradio，十分钟的事。
  • 图像层：ComfyUI 走节点式的 Stable Diffusion 工作流；diffusers 在库的层面搭管道。
  • 语音层：转写这一项，Whisper 基本没有对手：多语言，鲁棒性高，社区还做了更快的 faster-whisper。

先看硬件：Ollama 的模型个个几个 GB 起，你能跑多大，取决于显存或统一内存。Mac 内存 16GB 往上，7B–13B 量化跑得很顺；PC 显存 8GB，7B 量化没问题，再往上就吃力——数字是粗略的，具体还得看量化档位和模型结构。别追最大的，跑得稳的小模型，比卡死的 70B 值钱。

推理工具按需求对号：

  • 就在本地聊天 → Ollama，ollama run 一条命令搞定。
  • 要一个 OpenAI 兼容 API 喂给别的应用 → LocalAI，账号不用注册，密钥也省了。
  • 多人用、吞吐要高 → vLLM，它的快来自 PagedAttention。
  • 只有 CPU，没有 GPU → llama.cpp，GGUF 量化，常用档位 Q4_K_M，轻量硬件也转得动。

向量检索，这三家里挑：

  • Qdrant：独立服务，查询能带过滤，生产项目选它。
  • LanceDB：嵌在应用里，不用起服务，数据就是本地文件。
  • Chroma：轻，原型期用它最方便。

嵌入模型接 sentence-transformers。

别第一天就把全家桶搭齐。先装 Ollama，跑通一个对话，确认硬件扛得住，再按需一层层加。全家桶是能跑，维护起来麻烦——真坏了，你连它坏在哪一层都说不清。

04 · 设计

设计工具：先定产出物，再挑软件

头一个问题不是用哪个软件，是你要画出来的东西长什么样：

  • 位图修图：GIMP 对标 Photoshop，功能齐全，界面老了点；Krita 偏数字绘画，笔刷手感好得多。
  • 矢量：Inkscape 对应 Illustrator；Gouache 跑在浏览器里，轻，改 UI、调品牌物料很顺手。
  • 快速草图：要个白板，Excalidraw 的手绘风正合适，产品讨论、头脑风暴都用它；tldraw 则是白板引擎，能嵌进你自己的产品。
  • 图表与原型：画架构图找 draw.io；做团队 UI 设计看 Penpot，开源 Figma 的正面竞争者，浏览器里多人协作，还能自托管。
  • 三维：这块是 Blender 的地盘，建模、渲染、动画、剪辑全包。
  • 视频剪辑：Kdenlive 是非线性剪辑器，多轨、滤镜、关键帧动画都齐。

按产出物对号入座：

  • 照片处理、截图标注、界面稿 → GIMP
  • 插画、概念图、分镜 → Krita，笔刷引擎和洋葱皮动画是它的强项
  • Logo、图标、任何要无限放大的品牌资产 → Inkscape，产出是 SVG
  • 会议白板、流程草图、不要求好看 → Excalidraw，手绘风就是它的卖点
  • 架构图、时序图、UML → draw.io，可以导出图片，也可以当 diagram-as-code 用
  • 团队 UI 设计、实时协作、设计交付 → Penpot，开源、可自托管
  • 建模、渲染、动画、视频 → Blender，一个工具管全流程

常见的错法是拿 GIMP 画插画、拿 Inkscape 修照片。工具没毛病，场景选错了而已。先确认产出物是位图、矢量还是白板，工具自然就定了。

05 · 系统

终端工具箱：把命令行变成工作台

这套终端配置可以直接抄，分四块：

  • 查：搜内容用 ripgrep（尊重 .gitignore、并行搜、大仓库也是毫秒级），找文件用 fd；fzf 能把列表变成模糊过滤，文件、历史、进程都行；zoxide 替掉 cd，按使用频率智能跳目录。
  • 看：看文件用带高亮的 bat（行号、感知 git 状态），看进程用 btop 或 htop，磁盘占用看 duf，哪个目录最占地方，dust 的树形视图一眼看出。
  • 管：会话交给 tmux（ssh 断了会话不死，detach 之后随时回来）；Git 和 Docker 有 TUI 版的 lazygit 和 lazydocker，暂存、提交、rebase、容器、镜像，全程键盘。
  • 运维：监控告警是 Uptime Kuma（多渠道通知、公开状态页）；网盘同步交给 rclone，各家云存储都能搬的瑞士军刀；备份用 restic 或 Borg，加密、去重、增量都有，restic 可选的云端后端更多。

还有两个少有人提的 shell 升级：atuin 把 shell 历史变成可搜索、可跨机器同步的库，不用再拿方向键翻半天；Nushell 是结构化数据的 shell，表格和对象直接过管道，思路跟 bash 完全是两回事，值得抽一天试。

不用一口气全装。先上 ripgrep、fd、fzf、bat 四件套，命令行立刻快一个量级，之后缺什么再补 tmux 和 lazygit。配置成本就一份 dotfile：全放进 ~/.config，用 git 管起来，换机器时整个工作台打包搬走。

06 · 问答

常见问题

「常用精选」和「小众优选」到底差在哪？

常用精选是天天上手的高频工具，小众优选名气不大，但各自解决某个具体问题。两者不分高下，编号只为引用方便（001–221 / 222–500）。反馈问题时直接报编号，比贴截图清楚得多。

星标数、语言、许可证这些数据哪来的？

精选条目的主语言和许可证来自各项目的 GitHub 仓库，LICENSE 文件或仓库页面，参考用，可能落后于仓库现状。热榜的星标数是抓取那一刻的实时值，本站不参与维护。分类按条目内容人工标注，个别可能标错。

热榜的入选规则是什么？

靠 GitHub Search API 自动抓取，窗口分三档：天（近 1 天创建、星标 200 以上）、周（近 7 天、500 以上）、月（近 30 天、1500 以上），按星标降序排。热榜页上点「窗口 天 / 周 / 月」切换，每档自带 10 分钟缓存，按「刷新热榜」就强制重抓。线上访问时，抓取和缓存都在本站的服务端函数里完成，浏览器不直接连 GitHub，不占直连额度。只有本地打开这份 HTML 预览、函数用不了时，才退回浏览器直连——未登录限每分钟 10 次，刷太勤会失败。失败不是页面坏了，等一会儿再刷。

想推荐收录一个软件，或发现介绍写错了，找谁说？

发封邮件到 myq13263221790@qq.com，附上仓库地址、问题出在哪、建议排第几号。收录的门槛是「本人装过、用过」，纯投稿一律不收——介绍和功能特点，得真用过才写得出。

为什么没有广告和埋点？

全站没有第三方脚本，没有分析，也没有用户追踪，统计跑在自己的服务端。「赞助商 / 推广 · 返佣」链接不多，每一处都标明是付费合作，目录排序和内容不受影响；不赞助也不会被降级或变慢。微信 / 支付宝 / 爱发电的赞助，只用来撑住更新的动力。

站上这些软件的版权归谁？

版权归原仓库作者所有，本站只整理数据、写介绍。每个软件遵循自己的开源许可证，MIT、GPL、Apache 都常见，一切以仓库为准。卡片上的许可证标注只是参考，要商用就去读仓库里 LICENSE 的原文。

07 · 效率

效率与办公：把笔记、任务和文档串成一条线

效率工具的坑不是不好用，是装了一堆互不相干：笔记归 A，任务归 B，文档归 C，到头来什么都找不到。先弄清自己的链路是「随手记 → 整理 → 产出」还是「协作 → 交付」，再一个环节一个环节地配工具。

要本地优先的笔记，三条路线各有各的脾气：

  • 双链与知识网络：Logseq 靠块引用和大纲理思路，适合边读边拆；思源笔记 是国产块级编辑器，块引用、数据库、本地存储都抠得很细。
  • 传统文件夹 + Markdown：Joplin 用起来最省事：同步支持 WebDAV、Nextcloud、S3，导出纯 Markdown，数据不会被锁死；Notesnook 的卖点是端到端加密，私密内容放它更放心。
  • 协作与数据库：AppFlowy 和 AFFiNE 都想当 Notion 的开源替代：前者偏文档 + 数据库，后者更接近在无限画布上做块编辑。

任务管理别急着上团队级看板。一个人用，taskwarrior 就够，命令行的瑞士军刀；再配一个 timewarrior，时间账也顺手记了。想要图形界面和看板，Vikunja 自己托管，数据不进别人的机房。

文档产出这块，幻灯片可以交给 Marp，Markdown 写的，改完当场导出 PDF。PDF 本身要折腾，就装一个本地工具箱 Stirling-PDF：合并、拆分、压缩、OCR 都在本机做，文件不必传到在线站点。

最后一条建议：笔记工具只养一个，用满三个月再谈换。迁移的成本远大于工具之间的差距。资料可检索，靠的是稳定的标签和命名习惯，而不是软件里哪个「杀手级功能」。

08 · 网络

网络与安全：从排查故障到加固边界

网络和安全类的工具，最好趁没出事就装好、挨个跑一遍。真到断网那天再去搜命令，往往连该用哪个都想不起来。

排查按「通不通 → 慢在哪 → 是什么流量」的顺序走：

  • 通不通：ping 先探可达性，traceroute 和 mtr 看路径和每一跳的丢包，mtr 相当于连续跑的 traceroute，查运营商节点的问题特别好用。
  • 慢在哪：点对点带宽用 iperf3 来测，gping 给 ping 配上图形，谁在吃流量，nethogs 一屏就能看清。
  • 是什么流量：命令行抓包用 tcpdump，要逐层拆开看就换 Wireshark；手工验证 HTTP 接口，先找 curl。

主动扫描和渗透测试，前提是目标归你所有，或拿到了书面授权：

  • 端口与服务识别，Nmap 是事实标准；要极快速扫完整个网段，用 masscan。
  • OWASP ZAP 和 Nikto 主要检查 Web 应用和服务器配置；想要一套完整的漏洞管理框架，是 OpenVAS。
  • 无线这边是 Aircrack-ng、Kismet；恢复密码用 Hashcat 或 John the Ripper。

日常加固反而朴素：DNS 层拿 AdGuard Home 或 Pi-hole 拦掉广告和跟踪；远程访问用 Tailscale 或 WireGuard 组个虚拟网络，管理端口别裸暴露到公网；要做内网穿透，常见的是 frp 和 sing-box。密码统一放进 KeePassXC 或 Bitwarden，想自己托管可以看看 Vaultwarden。

最后提醒：工具越强，越要有边界感。扫描、爆破、抓包，只对自家的或明确授权过的目标动手。

09 · 媒体

媒体与娱乐：播放器、剪辑和音频工作台

挑媒体工具，别看功能表有多长，先想清楚你的产出物：看片、剪片、做字幕，还是做音乐。场景定了，工具才好配。

只想看片的话，按平台挑：

  • 本地万能播放：mpv 轻量、脚本能力强，键盘用户多半偏爱它；格式再刁钻，找 VLC，它的格式支持最广；macOS 上的 IINA 等于给 mpv 套了层原生壳。
  • 家庭影音中心：本地媒体库交给 Kodi；要多端串流，用 Jellyfin，完全开源；Plex 体验成熟，代价是掺着闭源组件。

视频这条链上，ffmpeg 是底层引擎，几乎所有图形工具背后都在调它。裁剪不想重编码，LosslessCut 几秒就能搞定；要做完整剪辑，Shotcut 跨平台，多轨和滤镜都齐；录屏、直播推流用 OBS Studio，压制输出再配一个 HandBrake。

音频这边：录音、降噪、剪切这类轻量编辑，Audacity 就够用；做音乐得上正经的多轨 DAW，用 Ardour；打碟是 Mixxx，双 decks、效果器都支持；音乐库让 Picard 自动抓专辑元数据；语音合成试试 Piper，本地就能跑，不用联网。

字幕和图片容易被漏掉：时间轴校对找 Subtitle Edit，特效字幕用 Aegisub；图片批量处理是 ImageMagick 的活，日常看图换个轻快的 Nomacs。

说到底：怎么看，是播放器的事；怎么改，归 ffmpeg 和剪辑器；怎么做出来，那是 DAW 的活。三件事，别指望一个工具全包。

10 · 自托管

自托管：从一台机器到一套服务

自托管最容易劝退人的，是第一天就想搭「全家桶」。慢一点反而稳：先有一台常开的机器，把一个真正用得上的服务跑通，再加监控和备份，编排和多节点是以后的事。

底座先选好。轻量场景 Docker 就够；介意守护进程就换 Podman，不用 root，跟 systemd 也更贴；机器数量上来了，再谈 Kubernetes。运维要图形界面，用 Portainer；反向代理和自动 HTTPS，交给 Traefik。虚拟化这一块，Proxmox VE 是一套成熟的一体化方案。

第一批值得上的服务，按用途挑：

  • 文件与同步：网盘加协作套件，Nextcloud 的地盘；点对点同步有 Syncthing；对接各家云存储用 rclone；想搭自己的文件中转站，Cloudreve 正合适。
  • 备份：Restic 和 Borg 都把加密、去重、增量做齐了；要紧的是异地存一份，没有异地副本的备份不能叫备份。
  • 媒体与订阅：影音归 Jellyfin 管；读 RSS，用 FreshRSS。
  • 监控：Uptime Kuma 盯着服务活没活，出事多渠道报警；指标和面板，Prometheus + Grafana。
  • 代码与密钥：私有 Git 用 Gitea 或 Forgejo；密钥交给 Vault；容器镜像仓库是 Harbor 的活。

几条经验：管理后台别裸奔在公网，走 VPN 或反向代理加认证。升级之前先备份配置和卷，滚动更新翻车是常态。先跑两周，再决定要不要长期维护——自托管的成本不在部署那一小时，在之后的每一次升级和排障。
